# 园区综合运维管理平台 · 个人作品

面向园区 / 厂区 / 政企单位的中后台运维管理系统，**一个人从需求到上线的完整实现**。
前端 Vue3 + TypeScript，后端 Node.js + SQLite，全部代码独立开发，数据为脚本生成的模拟数据。

## 技术栈

**前端**：Vue3（Composition API + `<script setup>`）· TypeScript · Vite · Vue Router · Pinia · Naive UI · ECharts · ExcelJS
**后端**：Node.js · Express · better-sqlite3 · JWT · bcryptjs
**工程化**：Vite 代理解决开发跨域；生产模式由 Express 同源托管构建产物

## 功能清单

### 1. 权限体系（RBAC）
- **菜单权限**：菜单由后端按角色返回，非管理员看不到「系统管理」
- **数据范围权限**：`ALL` 全量 / `REGION` 本区域 / `SELF` 仅本人相关，作用于设备、巡检任务、工单、告警、报表所有统计
- **操作权限**：`device:edit` / `inspection:plan` / `part:edit` / `system:*` 等权限点在路由与接口双层校验
- 角色 × 菜单权限矩阵可视化

### 2. 设备台账
- 关键词 / 类型 / 区域 / 状态 组合筛选 + 分页
- 新增、编辑、删除（含二次确认）
- **保养计划**：维护保养周期与下次保养日期，7 天内到期与已逾期设备可查询并预警
- **批量导入 Excel**：提供模板下载，逐行校验并回显失败行号与原因
- **导出 Excel**：按当前数据权限导出全量，带表头样式与边框
- **打印台账**：独立打印样式，自动隐藏侧边栏与操作列

### 3. 巡检管理（业务闭环主线）
- **巡检计划**：按区域 / 设备类型 / 周期（每日 / 每周 / 每月）配置，检查项清单可自定义
- **巡检任务**：按启用中的计划生成当日任务，支持按状态、所属计划、关键词筛选
- **现场执行**：逐项登记「正常 / 异常」，可关联设备编号与填写备注
- **异常自动转单**：提交时发现异常项，自动生成对应**告警**与**工单**（优先级「高」、带 SLA 时限、注明来源任务号）；整段逻辑在单个数据库事务内完成
- 巡检完成量趋势与区域分布统计

### 4. 工单中心
- 状态机流转：`待受理 → 处理中 → 待验收 → 已闭环`（待验收可打回处理中），非法流转在后端拦截
- **派单 / 转派**：指派处理人并记录响应时间，时间轴留痕
- **SLA 时效**：按优先级设定响应与处理时限（高 2h / 8h，中 8h / 24h，低 24h / 72h）；超时工单实时标记、自动置顶，支持「仅看超时」筛选
- **备件领用**：处理工单时领用备件，校验库存并即时扣减，领用记录挂在工单详情下
- 流转时间轴记录操作人、动作、备注与时间

### 5. 备件库存
- 备件台账：编码 / 规格 / 单位 / 库存 / 安全库存 / 单价 / 供应商
- **低库存预警**：库存低于安全库存自动标记，首页与列表均有提示
- **出入库管理**：手动入库 / 出库；出库校验库存充足性，拒绝超领与负数
- **流水可追溯**：每次变动记录「变动前 → 变动后」库存、关联工单、操作人与备注

### 6. 告警中心
- 等级（紧急 / 重要 / 次要 / 提示）与状态筛选
- 等级分布柱状图 + 近 30 天趋势折线图
- 一键标记已处理

### 7. 首页看板
- 4 张核心指标卡（设备总数、告警设备、待受理工单、未处理告警）
- 4 张业务待办卡（待执行巡检 / 超时工单 / 低库存备件 / 待保养设备），**可点击直达对应模块**
- 6 张 ECharts 图：告警趋势、工单状态分布、设备区域分布、设备类型构成、巡检完成量、备件出库量
- **所有数据受角色数据范围约束**，切换账号即可看到差异

### 8. 报表中心
- 维度（区域 / 类型 / 状态 / 工单状态 / 告警等级）× 图表类型（柱 / 饼 / 线）自由组合
- 在线预览 + 导出 Excel + 打印

### 9. 系统管理
- 用户管理：增删改、启停、重置密码
- 角色权限：数据范围配置 + 权限矩阵
- 数据字典：下拉选项统一维护
- **操作日志**：登录、增删改、工单流转与派单、巡检执行、备件出入库等关键动作全部留痕，支持按关键词与账号检索

## 快速开始

```bash
npm install          # 安装依赖
npm run seed         # 生成演示数据（200 设备 / 500 工单 / 1000 告警）
npm run dev          # 同时启动后端 3001 与前端 5173
```

打开 http://localhost:5173 ，用上表任一账号登录。

> 国内网络建议加镜像：`npm install --registry=https://registry.npmmirror.com`

其他命令：

```bash
npm run build        # 构建前端到 dist/
npm run preview      # 预览构建产物
```

生产部署时先 `npm run build`，再 `npm run dev:server`，Express 会直接托管 `dist/`，前后端同源。

## 代码质量与自测

```bash
npm run lint        # ESLint：0 error / 0 warning
npm run typecheck   # vue-tsc 类型检查：0 错误
npm run test:api    # 接口自测：69 项断言（服务需已启动）
node scripts/smoke-ui.mjs   # 前端冒烟：无头浏览器逐页检查 12 个路由 + 截图
npm run check       # lint + typecheck
```

接口自测覆盖 11 个维度：基础可用性、认证、权限点、数据范围、**越权探测**、业务规则、参数边界、
**巡检闭环**、**备件库存规则**、**工单 SLA**、**新模块权限**。

开发过程中它真实抓出并修复了 8 个缺陷，其中：
- **3 个越权漏洞**：主管可读区域外设备、专员可读他人设备与工单
- **1 个权限粒度问题**：「执行巡检」与「维护巡检计划」共用一个权限点，导致专员能删除巡检计划
- **1 个时间口径问题**：业务时间用 UTC 落库、SLA 却按东八区解析，超时判定整体偏 8 小时

这类问题手工点页面发现不了 —— 界面上根本不会出现越权的入口，时间偏差也只会让数据「看起来有点怪」。

## 设计说明

- **不套现成后台框架**：布局、路由守卫、请求层、权限模型均手写，体现从零搭建能力
- **权限双层校验**：前端按权限点隐藏入口，后端在中间件层再次校验，前端绕过也无效
- **数据范围下沉到 SQL**：`scopeFilter()` 统一生成 WHERE 条件，避免在每个接口重复写过滤逻辑
- **导入失败可定位**：逐行处理并回显「第 N 行：原因」，而不是整批失败
- **骨架屏 / Loading / 空状态 / 错误兜底**：接口异常有统一提示，列表为空有空状态
